## 二、工具怎么装（换新电脑时照着来）

1. **Node.js 18+**（本机 24.18.0）→ `node -v` / `npm -v` 能出版本
2. **HBuilderX 标准版** 解压到 `D:\HBuilderX`（绿色版免安装；路径不要带空格/中文）
   - 首次用打包功能会提示下载 App 打包插件，**下载完必须重启 HBuilderX** 菜单才完整
   - 登录 DCloud 账号（云打包强制登录），且**账号必须绑定手机号**，否则云端直接报错
3. **依赖**：工程根目录 `npm install`（⚠ 别加 `--prefer-offline`，会命中过期缓存误报"版本不存在"）
4. **adb（可选）**：本机目前**没有** adb。要用 `adb install` / `adb logcat` 时再装 Android 平台工具并加进 PATH；不用 adb 也能装机（手机连电脑拖 APK，或用微信/网盘传）
5. **VS Code**：装 Vue 官方插件（Volar）+ SCSS 语法支持即可，无需别的
6. **Git（建议）**：本机已装（`D:\Git`），但工程还没建仓。建议先 `git init` 后把当前代码提交一次，作为**出包前的还原点**（改坏代码能一键回退）

## 三、需要掌握哪些知识

### ① 必会（日常 90% 的时间用得上）

- **Vue 3 基础**：组件、`ref/reactive`、`props/emit`、`v-if/v-for`、`computed`、生命周期
- **uni-app 四件套**（与普通 Vue 项目最大的差别）
  - `src/pages.json`：**页面路由（38 个）+ 全局样式**（`globalStyle.navigationStyle: custom` 关掉系统导航栏）；**新增页面必须在这里登记**。⚠️ 底部导航**不在 pages.json 的 `tabBar` 里**，而是自绘组件 `src/components/common/CustomTabbar.vue`（emoji 图标 + `:class="{ active: ... }"` 程序切换选中态）
  - `src/manifest.json`：**应用配置**（AppID、包名、版本、图标、权限）
  - `src/App.vue` / `src/main.js`：全局入口（全局样式、Vue 插件挂载）
  - 生态差异：单位用 **rpx**（750 设计宽度自适应）、页面生命周期用 **`onLoad` / `onShow`**、系统能力调用统一走 **`uni.xxx`**（`uni.request` / `uni.navigateTo` / `uni.chooseImage` / `uni.setStorageSync`…）
  - **条件编译**：`#ifdef APP-PLUS` … `#endif`，一份代码按平台分叉
- **npm 脚本**：`npm run dev:h5`（浏览器调样式最快）、`dev:app`、`build:app`、`pack:app`
- **请求链路**：`src/utils/request.js`（拼 `BASE_URL`、自动带 Bearer、401 清登录态跳登录页）→ `src/api/*.js` → 页面

### ② 会用就行（不用背，知道去哪查）

- **版本对应规则**：`@dcloudio/*` 的 `3.0.0-5020420260813003` ↔ **HBuilderX 5.24**；`npm run check:version` 会自动验三处是否一致
- **HBuilderX 界面**：打开目录、发行 → 原生 App 云打包、运行 → 运行到手机或模拟器
- **PowerShell / adb** 少量常用命令（见第四节速查）
- **PC 端抓包排错**：`npm run dev:h5` 在浏览器里用 F12 看请求，比手机上猜快得多

### ③ 红线（背下来，本项目踩过的坑都在这）

1. **编译器版本必须等于 HBuilderX 版本**，否则启动弹「版本不匹配」→ 打包前先 `npm run check:version`
2. `npm run build:app` 会**清空 `dist/build/app`**，放在里面的 APK 会被删且不可恢复 → **APK 一律放 `release\`**
3. 打包前 **HBuilderX 必须在运行**（`npm run pack:app -- -Open`），否则任务静默不提交
4. 云端排队期间**别 `-Cancel` 重提**，会丢已排位次（云端也明确说"不要反复打包"）
5. 云打包给的下载链接**不带 `.apk` 后缀、只能下 5 次**，必须及时拉回本地
6. `npm install` **别加 `--prefer-offline`**（会命中过期缓存误报版本不存在）
7. 改 `manifest.json` / `pages.json` 后**必须重新 `build:app` + 重新打包**，APK 不会自己跟着变

### ④ 可以先不管

Android 原生开发（Java/Kotlin）、Gradle、Android Studio、keystore 自签名（DCloud 云端证书托管）、iOS 打包（需额外条件）——这些 DCloud 都替你做了。

## 五、APK 是怎么封装出来的

### 原理：你的"网页" + DCloud 的"安卓壳"

```
src/*.vue 源码
   │  npm run build:app            ← uni-cli + Vite 只做“前端编译”，不碰安卓
   ▼
dist/build/app/                     ← 纯前端资源：app-service.js、app.css、pages/、static/
   │                                 + manifest.json（里面写死 compilerVersion: "5.24"）
   │  npm run pack:app            ← HBuilderX cli 把资源压成 __UNI__F1A3968.wgt 上传云端
   ▼
DCloud 云打包机                      ← 把资源塞进 DCloud 的安卓运行时（壳，引擎 hbuilder 1.9.9.82669）
   │                                 + 你的包名 com.lianou.app、应用名、图标、权限、证书签名
   ▼
临时下载链接（不带 .apk 后缀、限 5 次）→ 拉回本地 release\
```

**关键认知**：APK = 你的网页资源 + DCloud 的安卓壳，所以「**编译器版本（资源里的 compilerVersion）**」必须等于「**运行时版本（壳/基座 SDK）**」，不等就会在启动时弹「版本不匹配」警告（详见 `APK打包与真机联调.md` 第八节）。

### 标准操作流程（六步，复制即用）

```powershell
npm run pack:app -- -Open                     # 0) 先启动 HBuilderX（不开会静默不提交任务）
npm run build:app                             # 1) 源码 → dist/build/app（⚠ 会清空该目录）
npm run check:version                         # 2) 三处版本一致才继续（必须全 [ OK ]）
npm run pack:app                              # 3) 提交云打包（免费队列，高峰要等半小时+）
npm run watch:pack -- -OutDir release         # 4) 盯队列，出包自动下载到 release\
# 装到手机，用 13700000000 / 123456 登录验收      # 5) 登录页有测试账号兜底分支
```

- 第 3 步**只是提交**，返回「已提交」≠ 打完；第 4 步才是等结果，从提交到出包实测约 **12 分钟**（排队 206 → 0 位，17:03:48 成功）
- 出包后 CLI 打印的链接形如 `https://app.liuyingyong.cn/build/download/<uuid>`（**临时地址、只能下 5 次**），`watch:pack` 会自动识别并下载，存成 `release\lianou-MMDD-HHmm.apk`，日志打 `DONE`
- 也可以在 HBuilderX 界面里点：**发行 → 原生App-云打包**（等价操作，界面版见 `APK打包与真机联调.md` 第四节路线 A/B）

### 「调试」和「打包」不是一回事

| | 运行到基座（调试） | 云打包（出包） |
| --- | --- | --- |
| 入口 | `npm run dev:app` + HBuilderX「运行 → 运行到手机或模拟器」 | `npm run build:app` + `npm run pack:app` |
| 产物 | 临时跑在 HBuilderX 的**标准基座**里（改完即时刷新） | 独立 APK，自带运行时，可发给别人安装 |
| 用时 | 秒级 | 排队 + 打包约 10–35 分钟 |
| 适用 | 开发期快速看效果 | 测试 / 验收 / 发版 |

> 常见误会：模拟器上看到的 App 其实可能是 **HBuilderX 标准基座**（包名 `com.HBuilder` / `HBuilder`），不是我们的包。云打包的 APK 目前只含 `arm64-v8a`，x86 模拟器装不上。

## 六、出问题先看这张表

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 启动弹「本应用使用 HBuilderX 5.15 编译，而手机端 SDK 版本是 5.24」 | 编译器 ≠ 运行时（工程依赖没和 HBuilderX 对齐） | `npm run check:version` → 三处统一到 5.24 → `build:app` + 重打包 |
| `npm run pack:app` 秒返回「已提交」但云端没任务 | HBuilderX 没开，cli 根本没提交 | 先 `npm run pack:app -- -Open`；脚本已改为红字报错 + `exit 1` |
| 云打包报「尚未绑定手机号」 | DCloud 账号未绑手机号 | https://dev.dcloud.net.cn/pages/user/info 绑定 |
| 云打包报「公共测试证书已停用」 | 证书类型选错 | 用**云端证书**（`--android.androidpacktype 3`，脚本已默认） |
| 一直「队列中」不动 | 免费队列排队（高峰 30 分钟+） | 等着，别 `-Cancel`；急可买「独享打包机」 |
| `watch:pack` 报「未出包/超时」 | 排队太久超出 `-TimeoutMin` | 加大 `-TimeoutMin`，或直接 `npm run pack:app -- -Status` 看位次 |
| 手机装不上 / 提示解析包错误 | APK 只含 `arm64-v8a`，装到了 x86 模拟器 | 换真机；或临时给 `manifest.json` → `abiFilters` 加 `x86` 重打（**仅测试包**） |
| 装完打开是空白 / 不是我们的界面 | 装的是 HBuilderX 标准基座 | 看包名：`adb shell pm list packages \| findstr lianou`，`com.lianou.app` 才是我们的包 |
| 手机上所有接口都失败 | `BASE_URL` 还是 `127.0.0.1`（手机上的 127.0.0.1 指手机自己）；或 Android 9+ 明文 HTTP 被拦 | 改 `src/utils/config.js` 为**后端电脑的局域网 IP**，后端监听 `0.0.0.0`、同 WiFi、防火墙放行端口 |
| 上次的 APK 找不到了 | 被 `npm run build:app` 清空了 `dist/build/app` | 出包后一律存 `release\`；已丢的无法恢复 |
| `npm install` 报「找不到某版本」 | 加了 `--prefer-offline`（命中过期缓存） | 去掉该参数重装 |
| 改了代码但 APK 没变化 | 只改了源码没重新构建/打包 | `npm run build:app` → `npm run pack:app` → `watch:pack` |

## 七、几个常见疑问

- **为什么不用 Android Studio / 不写 Java？** 这是 uni-app 前端工程，安卓壳与签名由 DCloud 云打包完成，本机连 JDK / Android SDK 都不需要。
- **H5 和小程序怎么出？** `npm run build:h5` → `dist/build/h5/`（可丢到任意静态服务器）；`npm run build:mp-weixin` → 用微信开发者工具导入 `dist/build/mp-weixin/` 再上传。
- **APK 能直接发给别人吗？** 能，独立安装包；但当前是**测试包**（云端证书、`versionCode 100`、接口地址还是本地/测试），正式发版需换正式证书、递增 versionCode、把 `config.js` 切到 `USE_PROD = true` 并填 `PROD_BASE_URL`。
- **一台电脑能同时开多个打包任务吗？** 不建议，免费账号排队本身就很长；且同一工程会互相覆盖产物。
- **出包要多久？** 实测提交到出包约 **12 分钟**（含排队），高峰可达 30–60 分钟；用「安心打包」（manifest 未改、无原生插件时可复用）会快且不占云打包次数。
