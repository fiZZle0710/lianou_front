## 三、09-15 版的编号规则（仍适用，最容易踩的坑）


| | 09-13 版 | 09-15 版 |
|---|---|---|
| 编号方式 | **全局连续** `#1` … `#96` | **按模块局部**，12 个模块各自从 1 开始 |
| 正文标注 | `### 59. POST /api/v1/...` | `#### 5.8 POST /api/v1/...`（`模块.序号`） |
| 接口数 | 96 | 106 |

**两者不是平移关系**：旧 `#1`=login / `#2`=logout / `#3`=me / `#5`=register / `#7`=send-code；
新 `1.1`=send-code / `1.2`=register / `1.3`=login / `1.6`=me / `1.7`=logout。
所以 **2026-09-14 写的几份前端文档里的 `#NN` 必须换算** → 见 `接口编号映射-09-13到09-15.md`。

**新约定（本项目内部）**：引用接口一律写「**方法 + 路径**」，编号只作辅助（例 `POST /api/v1/projects/<id>/apply`（新 5.5））。这样后端下次重排编号，我们不用再重映射一遍。

## 六、⚠️ 时间格式（新文档明确的坑）

- 后端所有时间字段是 `.isoformat()` 输出，形如 `2026-09-15T10:30:00`，**无时区后缀**（UTC 存储，不带 `Z`/`+00:00`）。
- **JS 里 `new Date('2026-09-15T10:30:00')` 会按本地时间解析** → 前端展示时间必须显式按 UTC 处理，否则会差 8 小时（`null` 表示该时间为空）。
